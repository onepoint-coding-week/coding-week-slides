The whole chain

Six steps, 45 minutes. Do them in order.

  1. One of you: Fork the project for the team. Invite the others.
  2. Everyone: Clone the team's fork.
  3. At the keyboard: New branch, page.py, check it in the app.
  4. At the keyboard: Push. Open the pull request to the main project.
  5. Team, then mentor: Checks green, the team reviews, the mentor merges.
  6. Everyone: Sync fork, git pull, run the app. Your names are there.

Minutage : 2:00 (cumul 4:30).

Parcourir les six étapes, sans détailler les commandes : ce sont celles de l'atelier GitHub de ce matin.

  1. Un membre forke le projet principal pour l'équipe, puis invite les autres comme collaborateurs du fork (Settings, Collaborators). Un étudiant qui le souhaite peut aussi avoir son propre fork.
  2. Chacun clone le fork de l'équipe : le clone du vrai projet est ainsi vérifié sur tous les portables dès aujourd'hui.
  3. Celui qui tape crée une branche, écrit page.py, lance l'application et vérifie que la page est dans le menu. uv run pytest : tests/test_pages.py ouvre chaque page pour chaque groupe de démo.
  4. Il pousse et ouvre la pull request, du fork de l'équipe vers le main du dépôt principal.
  5. Les vérifications passent au vert, l'équipe relit dans Files changed, puis appelle l'encadrant, qui relit et fusionne.
  6. Chacun clique sur « Sync fork » sur GitHub, fait git pull et lance l'application : les prénoms sont sur la page, sur sa propre machine.

Ceux qui ont fini lisent leur fichier de tests, dans tests/ : c'est le programme de 16h20.
