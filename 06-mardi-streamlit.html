Part 1 · Streamlit

Draw the page.

Transition. Première partie : uniquement Streamlit, ce qui s'affiche et comment la page tourne. Pas de base de données ici.

A page is a Python script

No HTML, no CSS. Each st. call adds something to the page.


import streamlit as st
st.title("Example feature")
name = st.text_input("Add a name")
if st.button("Add") and name:
    st.success(f"Hello {name}!")

Minutage : 2:30 (cumul 3:00).

Lire le code ligne à ligne. C'est la page 00_example, presque telle quelle. Chaque appel st.quelque_chose dessine un élément, de haut en bas, dans l'ordre du script.

Every click runs it again

From the first line to the last.


count = 0
if st.button("Add one"):
    count = count + 1
st.write(count)
# always 0 or 1. Why?
Must it last? Not in Streamlit: see part 2.
Only for this page? Keep it in st.session_state.

Minutage : 4:00 (cumul 7:00).

L'idée la plus importante de la matinée. Lire l'exemple : count repart de 0 à chaque clic, la page n'affiche jamais plus que 1. Demander à la salle pourquoi avant de montrer la réponse.

Les deux sorties, à droite :

  • ce qui doit durer ne peut pas vivre dans Streamlit : c'est la partie 2, la base de données ;
  • une valeur de la page seulement (une étape, un choix temporaire) peut aller dans st.session_state.

Cette idée explique presque toutes les surprises de la semaine.

The form

Several fields, sent together, in one click.


with st.form("new_wish"):
    title = st.text_input("Gift idea")
    price = st.number_input("Price", min_value=0.0)
    sent = st.form_submit_button("Save")
if sent:
    st.success(f"{title}: {price} €")
Typing No rerun while you type.
Clicking Save All fields arrive together.

Minutage : 6:00 (cumul 17:00).

Lire l'exemple : le formulaire regroupe les champs, et la page ne se relance qu'au clic sur le bouton du formulaire. Taper dans un champ ne relance plus rien. Au clic, tous les champs arrivent ensemble.

Facultatif, s'il reste du temps : montrer une page d'équipe réussie, repérée pendant l'atelier par les encadrants.

Part 2 · The database

Keep the data.

Transition. Deuxième partie : la base de données, ce qui survit au clic et au redémarrage. On répond ici à la question laissée ouverte par « Every click runs it again ».

Database, table, column, row

A database is a set of tables. A table looks like a spreadsheet.

  • Database: a file that keeps the data, between clicks and restarts.
  • Table: one kind of thing: groups, participants, wishes.
  • Column: one property, with a type.
  • Row: one or several columns resulting from a query.

Minutage : 2:00 (cumul 25:00).

Pour ceux qui n'ont jamais vu de base de données. L'image du tableur suffit : une table = un onglet, une colonne = une colonne typée, une ligne = un élément.

Deux colonnes à faire remarquer :

  • id : un numéro unique par ligne, donné par la base (la clé primaire) ;
  • group_id : le numéro d'une ligne d'une autre table. C'est comme ça que les tables se relient : Alice, Bruno et Chloé sont dans le groupe 1, « Office party ».

SQLite: a database in one file

Everything lives in app/data/app.db.

One file

No server to start. Delete app.db: the app rebuilds it with the demo groups.

Already in Python

import sqlite3. Nothing to install, on any laptop.

Real SQL

Same tables and rules as the big databases: NOT NULL, UNIQUE, links between tables.

The tests use their own temporary database: your data stays safe.

Minutage : 2:00 (cumul 27:00).

Pourquoi SQLite ici, plutôt que PostgreSQL ou un service cloud :

  • un seul fichier, pas de serveur, pas de compte : on clone, on lance, ça marche ;
  • le module sqlite3 est livré avec Python ;
  • c'est du vrai SQL : ce qu'ils apprennent ici sert ailleurs.

Les tests passent par la variable SANTA_DB : ils écrivent dans une base jetable, jamais dans app.db.

La limite : une seule machine, peu d'écritures en même temps. Pour un Secret Santa, c'est largement assez.

tables.py: the database without SQL

A table name and a dictionary. That's all.


find(db, "wishes", {"participant_id": me["id"]}, order_by="-price")
find_one(db, "groups", {"id": 3})
count(db, "wishes", {"participant_id": 5})
insert(db, "wishes", {"participant_id": 5, "title": "Book"})
update(db, "groups", {"budget": 30}, {"id": 3})
delete(db, "wishes", {"id": 12})
create_table(db, "example_names", {"name": "TEXT NOT NULL"})

Minutage : 4:00 (cumul 32:30).

app/tables.py est un module, pas une classe : une fonction par action, qui écrit le SQL à leur place. On n'a pas besoin de connaître SQL pour finir le niveau 1.

  • find renvoie une liste de lignes (vide s'il n'y en a pas), find_one une ligne ou None, count un nombre, insert l'id de la nouvelle ligne.
  • where : chaque paire doit correspondre (ET). None veut dire « vide » (NULL), une liste veut dire « une de ces valeurs ».
  • order_by : "name", ou "-price" pour le plus grand d'abord.
  • Pas de comparaison (« prix supérieur à 10 ») ni de jointure : on récupère les lignes et on filtre en Python. index_by transforme une liste en dictionnaire par id, pour retrouver un nom à partir d'un participant_id.
  • Sécurité : les valeurs partent toujours à part (les ? de sqlite3). Un nom comme « x'; DROP TABLE users » reste un simple texte.
  • update et delete exigent un where : impossible de vider une table par erreur.
  • create_table ajoute une colonne id tout seul, et ne fait rien si la table existe déjà : on peut l'appeler à chaque démarrage.

Besoin d'autre chose ? db.execute("...", (valeurs,)) marche toujours, avec un ? par valeur.

page.py asks, logic.py decides

The page collects and shows. The rules live in logic.py.


logic = import_module("features.03_wishlist.logic")
title = st.text_input("Gift idea")
if st.button("Add"):
    try:
        logic.add_wish(db, me["id"], title)
        st.success("Added")
    except ValueError as error:
        st.error(str(error))
  1. Ask with widgets.
  2. Call one function of logic.py.
  3. Show the result, or the error.

Minutage : 3:30 (cumul 36:00).

La slide qui assemble les deux parties : Streamlit pour demander et afficher, logic.py et la base pour décider et garder. C'est le squelette du guide étudiant, section 3. Trois choses à montrer :

  • import_module : le nom du dossier commence par un chiffre, un import classique est impossible ;
  • la page appelle une fonction de logic.py, jamais de calcul dans la page (une boucle, une somme : c'est pour logic.py, là où les tests l'atteignent) ;
  • logic.py lève une ValueError avec un message clair ; la page l'attrape et l'affiche avec st.error.

Exemple tiré de 03_wishlist : add_wish.
