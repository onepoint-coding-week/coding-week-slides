What is TDD or Test Driven Development?

Test Driven Development is a technique where you write your test cases BEFORE you write any implementation.

Tests drive and dictate the code that is developed.

It is:

  • An indication of intent
  • A living specification for your application

Some might argue that the tests are part of the documentation!

What is a KATA?

A kata is a small, self-contained coding exercise that you repeat to practise a technique. The word comes from MARTIAL ARTS!

In programming, a kata usually has:

  • A tiny, well-defined problem.
  • A focus on how you code, not what you build.
  • Short time-boxes, sometimes done in pairs (one types, the other guides) and redone from scratch to try a different approach.

The loop

Test, code, validate test, clean up. REPEAT.

  1. Red: Write one test. Run it: it fails.
  2. Green: Write the simplest code that makes it pass.
  3. Refactor: Clean up if necessary. Run again: still green.

A test you never saw fail proves nothing! Make sure you get a failing test before starting to write your code.

Minutage : 12:00 (cumul 16:30). La démonstration, en direct, dans l'éditeur et le terminal côte à côte, police très grande.

Suivre la fiche du speaker, étapes 2 à 6, et dire les phrases telles quelles :

  • Le test : "The name of the test is a sentence: it says what the code must do. I describe WHAT I want, not HOW."
  • Premier rouge, ImportError : "Red. This is not a mistake: the test tells me the function does not exist yet. Red is my shopping list."
  • Deuxième rouge, avec pass : "Still red, but the message changed: now the function exists, and it gives the wrong answer. Always read the red message."
  • Vert avec return True. Laisser réagir la salle : "Yes, return True. It is the simplest code that makes the test pass. If I write more, I write code that no test checks. The next test will force me to do better."
  • Refactor : les types et la docstring, toujours vert. "Refactor means: the behaviour does not change, and the tests prove it. In your feature, this is when you commit."

Cycle 3, on the board

A negative price is a mistake.


import pytest
def test_a_negative_price_is_a_mistake():
    with pytest.raises(ValueError):
        gift_fits(-5, 20)
Red No error yet: the test fails.
Green Add the check in gift.py.
Refactor Still green? Three tests now protect the function.

Minutage : 4:00 (cumul 4:15).

En direct : écrire le test avec pytest.raises, le lancer, le voir rouge. Puis écrire le code au tableau : le if qui lève ValueError, avant le return. Relancer : vert. Ce code-là n'est pas sur la slide, il s'écrit en direct.

Demander à la salle où placer le if, et pourquoi avant le return. Rappeler : un test qui attend une erreur ne passe que si l'erreur est levée.

The cents trap

Bonus B1 hid a surprise. Did you find it?


>>> 0.1 + 0.2 <= 0.3
False
>>> 0.1 + 0.2
0.30000000000000004

Two items at 0.10 and 0.20 don't fit a budget of 0.30.

A computer stores most decimals with a tiny error.

Question: how would you count money?

Minutage : 3:00 (cumul 7:15).

Si un binôme l'a trouvé (les encadrants l'ont signalé), le faire venir au tableau et le montrer. Sinon, le montrer soi-même en une ligne dans le terminal Python.

Ne pas donner la réponse toute faite : poser la question de la slide. La réponse attendue : compter en centimes, avec des nombres entiers. Ce piège existe dans tous les langages, pas seulement en Python.

Minutage : 2:15 (cumul 9:30).

Faire le lien avec la suite. Chaque feature a son fichier de tests, tests/test_NN_nom.py, déjà écrit : de 6 à 11 tests. Tant que logic.py n'existe pas, ils sont tous « skipped ». Dès que l'équipe crée logic.py, ils passent au rouge.

La boucle est exactement celle du kata : choisir un test rouge, écrire le code le plus simple, le voir vert, relancer tous les tests, commiter. Puis le suivant. Une seule différence : ici, les tests sont déjà écrits. À eux de les lire, phrase par phrase.

La phrase de la fiche du speaker, adaptée : "Your test file is your specification. Pick one red test, make it green, commit. Again and again. That is exactly what you just did."
